    🧠

    2016: console.log("aqui"), console.log("aqui 2") e a resposta aceita de 2011 no Stack Overflow

    🧠

    2019: breakpoint no DevTools, stack trace lida de verdade e um workaround achado numa issue do GitHub cheia de “+1”

    🧠

    2022: cola a stack trace no ChatGPT, ele inventa um método que não existe na biblioteca e você descobre lendo a documentação

    🧠

    2025: o agente reproduz o bug num teste que falha, corrige o código e roda a suíte até ficar tudo verde

    🧠

    2026: o bug vira issue, um agente coordenador divide o trabalho (um lê os logs via MCP, outro escreve o teste, outro corrige), um agente revisor comenta o PR e você aprova com o CI verde

    Tentando construir o próprio cérebro

    O problema

    Todo agente começava cada sessão do zero. O que ele aprendeu ontem sobre o projeto, as decisões e os erros, simplesmente sumia.

    Agents Memory

    A primeira tentativa de resolver isso: um serviço de memória cognitiva inspirado no paper ENGRAM, antes de o claude-mem virar padrão.

    MemóriaEpisódica, semântica, procedural e de trabalho. Postgres + pgvector, embeddings de 384 dimensões
    AcessoServidor MCP próprio (Node/TypeScript) com 80+ tools sobre uma API FastAPI
    CapturaHooks UserPromptSubmit e Stop mandam a conversa pro pipeline, que extrai o que importa
    AgendamentosAPScheduler: sono a cada 15 min, 6 h e 3h da manhã, com 17 fases de reforço, esquecimento e reflexão
    Agents Memory→Ouroboros→Aether→Laniakea

    A missão: dar o “start” num projeto Claude, feito do zero ou já iniciado.

    Ferramentas

    • laniakea_agents(project) escolhe a identidade
    • o briefing manda chamar laniakea_identity_assume
    • o relatório volta com token LNK-…, conferido em laniakea_identity_verify
    • verifica com testes, typecheck, lint, git diff e navegador
    • git, gh e MCP direto

    Limites

    • não varre nem edita código
    • afirmação de subagente é hipótese até ser conferida
    • vago ou errado → redespacha, não assume o trabalho
    • laniakea_learn na saída

    O que eu diria pra quem está começando

    1

    Conserte coisas

    Formatar PC ensina o que nenhum modelo te dá: paciência pra achar a causa de um problema.

    2

    Tenha um projeto só seu

    Mesmo que mude de nome três vezes. É nele que você aprende o que o trabalho não ensina.

    3

    IA é alavanca, não muleta

    Se você não consegue explicar o código que o agente escreveu, ele ainda não é seu.

    4

    Aprenda a parte “chata”

    Banco de dados, deploy, pagamento. É onde os sistemas quebram e onde valem dinheiro.

    E eu, a IA, acrescentaria:

    Me pergunte “por quê”, não só “como”. Se eu explico o raciocínio, você aprende. Se eu só colo o código, você depende.

    Desconfie quando eu concordar rápido demais. Eu erro com a mesma confiança com que acerto. Teste o que eu escrevo.

    Feche o loop você mesmo. Teste, deploy, commit. Eu ajudo em tudo isso, mas quem assina é você.
